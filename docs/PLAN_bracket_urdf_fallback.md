# Fallback Plan — Port the Gavin 90° hand bracket into the URDF pipeline (Option 1)

**Status:** fallback. Primary approach is to switch the sim to the colleague's USD assets
(`dual_franka_orca_physics.usda` + `orca_v1`). Execute this plan only if the USD switch
does not work out. This keeps the existing **URDF** pipeline
(`sim_envs/assets/franka_orca_{left,right}.urdf` generated by `generate_combined_urdf.py`,
loaded by `sim_envs/franka_orca_bimanual_cfg.py`) and just fixes the hand mount.

## Problem being fixed
The Orca hand is currently mounted to the Franka flange "straight":
`panda_link8_to_{side}_hand` has `rpy="0 0 -0.7853981633974483"` (just the −45° flange yaw).
The real robot uses a **"Gavin 90° mount"** bracket — the hand hangs ~90° (≈105° net)
to the wrist axis. Because the URDF never had the bracket, the sim hand orientation is wrong,
and the `ARM_SIM_FROM_REAL` j6 offset of **+π/2** was a *software fake* of that 90° bend
(only valid while wrist-roll j7≈0; it diverges during the task). Real `j6 ∈ [−0.55, +0.07]`,
real `j4 ∈ [+0.73, +1.0]` — neither fits a textbook Panda, confirming a convention offset.

## Transform already extracted (USD row-vector convention; `dual_franka_mounted_visual.usda`)
`Mounted_Gavin` (rel `panda_link8`) authored `rotateXYZ=(90,0,0)`; right side uses scale
`(-0.001,0.001,0.001)` (mirror). Composing `R_net = R_orca_local · R_gavin_local`
(remove the 0.001 / 1000 mesh scales; right side has det<0 = reflection):

- **LEFT** net `panda_link8 → orca_v1 root`:
  - rpy (URDF Rz·Ry·Rx) ≈ **(roll 105.0°, pitch 0°, yaw 180°)** = `(1.8323, 0.0, 3.1416)` rad
  - orca_v1 root axes expressed in `panda_link8`:
    `+X → (−1, 0, 0)`, `+Y → (0, 0.2585, 0.966)`, `+Z → (0, 0.966, −0.2585)`
  - i.e. the hand extension (+Z) points along flange **+Y, slightly −Z** (perpendicular to wrist).
- **RIGHT** is the mirror (negative-X Gavin scale); recompute from its matrices, don't assume.

Re-extract with this snippet (host `~/.venvs/dz_h5/bin/python`) if needed — the matrices are
the `matrix4d xformOp:transform` rows under `Mounted_Gavin` and `Mounted_Orca` for each side
(lines ~380/401 LEFT, ~689/789 RIGHT in `dual_franka_mounted_visual.usda`):
```
R = rows / |scale_per_row|        # strip mesh scale; right Gavin row0 scale is negative
R_net = R_orca @ R_gavin          # row-vector chain orca→gavin→link8
rpy   = decompose(R_net.T)        # to URDF Rz*Ry*Rx (column-vector) convention
```

## ⚠️ Frame-reconciliation caveat (the one real unknown)
`R_net` orients the **orca_v1.usd** asset root. Our URDF uses **orcahand_description**, whose
root frame may differ by a constant rotation `R_frame` (orcahand_root → orca_v1_root).
Both appear to use **+Z = hand extension** (orcahand: `right_wrist` at `xyz≈(0.04,0,0.105)`;
orca_v1: CarpalsAssembly at `z≈+0.141`), so `R_frame` is likely just a **yaw/roll about Z**
(palm-normal / finger-spread alignment) — but this MUST be confirmed by render, not assumed.
The final URDF mount = `R_frame_corrected ∘ R_net`, tuned so the rendered hand matches the
real `setup.MOV` / h5 frames.

## Steps
1. **Re-derive `R_net` and translation** for BOTH sides from `dual_franka_mounted_visual.usda`
   (script above). Also pull the **translation** offset of the hand root relative to
   `panda_link8` (the matrix 4th row, minus the Gavin/Orca mesh-origin offsets — verify the
   hand sits on the flange, ~0–3 cm, not 0.4 m which is the asset-internal origin).
2. **Set the mount in `generate_combined_urdf.py`:**
   - Convert `R_net` to `MOUNT_RPY` (the generator already passes `mount_rpy`/`mount_xyz` to
     `combine_franka_orca`). Likely need a **per-side** mount (left vs mirrored right) — add a
     `mount_rpy_right` or compute it from the right matrices, since the existing `-pi/4`-only
     default is symmetric but the Gavin mount is not.
   - Keep `mount_xyz` from the extracted translation (small offset).
3. **Fix j6 (the bracket replaces the +π/2 fake):**
   - In `franka_orca_bimanual_cfg.py`, change `ARM_SIM_FROM_REAL` j6 from **+π/2 → 0**
     (keep j1=−π/4 and j4=−π — those are arm-reach fixes, unaffected by the wrist bracket).
   - **Widen the URDF j6 limit** lower bound (textbook −0.0175 → ≈ −0.6/−1.0) so the real
     small-negative wrist values aren't clamped (`generate_combined_urdf.py` `panda_joint6`
     limit). Alternatively pick the minimal j6 offset that stays in-range AND in-pitch — but
     widening is cleaner because any nonzero offset shifts the wrist pitch.
4. **Regenerate** URDFs: `python3 sim_envs/assets/generate_combined_urdf.py`.
5. **Verify by render (the loop that actually pins it down):**
   - `sudo bash docker/scripts/run_snapshot_frame0.sh` (frame 0) and `--frame 1000`.
   - Compare hand orientation to `setup.MOV` (wrist horizontal ⇒ hand points down) and to the
     h5 aria/oak-d frames. Use `eval_utils/multi_hypothesis_frame0.py` to sweep small
     yaw/roll corrections (`R_frame`) in ONE Isaac run until the palm/finger-spread matches.
   - Then full `sudo bash docker/scripts/run_replay_sidebyside.sh --stride 3` to confirm the
     bracket holds through motion (and that removing the +π/2 fake didn't regress tracking).
6. **Left/right consistency:** confirm the right hand (chiral mirror) reads correctly with the
   right-side mount; the generator already mirrors the *hand geometry* — ensure the mount
   transform is mirrored too (negative-X scale equivalent ⇒ flip the appropriate rpy sign).
